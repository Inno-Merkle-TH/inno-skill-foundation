# QE Glossary

| Term | Operational meaning |
|---|---|
| Acceptance criterion | Agreed observable behavior used to decide whether a requirement is satisfied |
| Test oracle | A justified source of expected results, not merely current implementation output |
| Risk-based testing | Selecting evidence based on likelihood/impact and uncertainty |
| Traceability | Requirement → risk → test → evidence → decision |
| Fixture | Controlled state/data/dependencies for a test |
| Idempotency | Repeating a defined operation does not create another intended effect |
| Optimistic concurrency | Rejecting a write whose expected version is stale |
| Authentication | Establishing who the caller is |
| Authorization | Deciding which action/resource that caller may access |
| Contract test | Checking an interface's agreed request/response behavior |
| Integration test | Checking collaborating components, including their boundaries |
| Exploratory testing | Learning, designing and executing tests around a charter |
| Severity / priority | Impact of a defect / scheduling importance |
| Flaky test | Inconsistent outcome without a corresponding intentional change |
| Liveness / readiness | Process responds / dependencies and behavior are ready |
| Reconciliation | Comparing eligible business records with valid observations |
| Consent exclusion | Intentional omission from analytics eligibility, not automatically data loss |
| RTO / RPO | Recovery-time target / acceptable data-loss target |
| SLO | A measured service-level objective under a defined scope |
| SPOF | A component whose failure defeats the intended availability |
| Provider / channel / OA | LINE identity/service scope / integration configuration / communication account |
| Shift-left | Bringing quality analysis and feedback earlier, not eliminating later verification |
